# Правила работы с файлами

- **Всегда** отдавай предпочтение встроенным инструментам `Grep` и `Read` для поиска и чтения файлов.
- **Никогда** не используй громоздкие shell-скрипты (например, на Python) для чтения или поиска по файлам, если задачу можно решить с помощью `Grep` и `Read`.
- Для независимых задач (например, поиск в нескольких файлах) используй параллельные вызовы инструментов в одном сообщении.

## Основные принципы работы

- Приоритет: корректность решения при минимальном расходе токенов.
- Выбирай наиболее простое решение, удовлетворяющее требованиям задачи.
- Не анализируй весь проект без необходимости.
- Начинай с файлов, непосредственно связанных с запросом.
- Расширяй область поиска только при необходимости.
- Используй точечный поиск вместо чтения больших файлов целиком.
- Не перечитывай файлы без необходимости.

## Изменение кода

- Вноси минимально необходимые изменения.
- Не переписывай существующий рабочий код без причины.
- Не проводи незапрошенный рефакторинг.
- Не добавляй функциональность, которую пользователь не просил.
- Не изменяй архитектуру без согласования.

## Использование инструментов

- Используй rg для поиска по проекту.
- Не сканируй зависимости, кеши, сгенерированные файлы и сборки без необходимости.
- Ограничивай объем вывода терминальных команд.
- Запускай только проверки, относящиеся к измененному коду.
- Не повторяй успешные проверки без причины.

## Коммуникация

- Для простых задач не составляй подробный план.
- Не пересказывай содержимое прочитанных файлов.
- Отвечай кратко и по существу.
- После выполнения сообщи, что изменено, какие проверки выполнены и какие проблемы остались.
- Завершай работу после выполнения требований задачи и необходимых проверок.
