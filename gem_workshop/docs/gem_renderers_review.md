# Обзор рендеров камней: что взять для «Грани»

Смотрел не «картинки», а реальные реализации: CPU-рейтрейсер GemRay,
WebGL-пример Three.js, простой шейдерный бриллиант, просмотрщик огранок
GCSViewer и дешёвый Unity-шейдер кристалла. Ниже — идеи, которые полезны
нашему движку, и границы применимости.

---

## 1. Что смотрел

### GemRay

- C++/FLTK, CPU-рейтрейсер граней.
- Камень — выпуклый многогранник из плоских граней.
- Луч идёт от глаза; считается вход, до **10 частичных внутренних отражений**.
- Есть Френель, преломление, TIR, поглощение.
- Дисперсия: три длины волны (красный/зелёный/синий), показатель преломления
  по Коши \(n = A + B/\lambda^2\).
- Несколько моделей освещения: равномерный свет, «случайное» небо с
  пятнами/софитами, косинусная модель.
- Есть **тень головы наблюдателя** — тёмный круг над камнем.
- Оптимизации: симметрия камня, подсказки последней грани для соседних
  пикселей, таблица затухания, многопоточность.

Источник: https://github.com/rwstrickland/GemRay

### Three.js diamond

- WebGL/Three.js, два прохода.
- Первый проход: **back-face normal buffer** — нормали задних граней.
- Второй проход: для каждого пикселя передней грани берётся задняя нормаль,
  считаются вход и выход луча, один акт преломления на входе и один на выходе.
- Три длины волны, дисперсия через `n_gem * REF_WAVELENGTH / wavelength`.
- Окружение — PMREM/room environment; Fresnel Schlick; roughness как
  приближение к матовости.
- Быстро, но нет полноценного многократного TIR: это скорее «красивый
  real-time fake», чем физический рейтрейсер.

Источник: https://github.com/tatsmaki/three-diamond

### Простой шейдерный бриллиант

- 9 плоскостей задают камень; `rayDiamond()` считает интервал входа/выхода.
- Внутри — до **25 отражений**, на каждом считается отражение/преломление.
- Три IOR (красный/зелёный/синий) дают цветное «огонь»-разложение.
- Фон — процедурная функция, а не HDR; это упрощает и удешевляет.

Источник: https://github.com/dunkaditya/diamond

### GCSViewer

- Просмотрщик файлов огранки GemCad/GemCut Studio.
- Четыре ортогональных вида: table (сверху), pavilion (снизу), side, 3/4.
- Плоская затенённая отрисовка, back-face culling, фиксированный свет;
  для павильона свет зеркалится снизу, чтобы низ не был чёрным.
- **Намеренно без преломления и дисперсии**: цель — видеть грани, встречи
  и ошибки огранки, а не «товарный» блеск.
- Цвет по tier’ам (ярусам огранки), отдельная штриховка для frosted facets.

Источник: https://github.com/loydb/GCSViewer

### Unity Crystal Shader

- `GrabPass` + screen-space refraction.
- Gaussian blur по захваченному экрану, Perlin/noise-смещение, rim light.
- Очень дешёвый и стилизованный; физически это не рейтрейсинг, а
  экранный эффект.

Источник: https://github.com/zVoyder/Crystal-Shader

## 2. Сравнение

| Реализация | Геометрия | Свет | Внутренние отражения | Дисперсия | Сильные стороны | Слабые стороны |
|---|---|---|---|---|---|---|
| GemRay | выпуклый многогранник | sky/spot/head shadow | до 10 | 3 λ, Коши | физичность, световые модели, оптимизации | CPU, нет объёма/включений |
| Three.js diamond | меш + back-face buffer | PMREM env | 1 вход + 1 выход | 3 λ | быстрый, красивый env | нет полного TIR |
| Shader diamond | 9 плоскостей | процедурный фон | до 25 | 3 IOR | простой, наглядный TIR | игрушечная геометрия/свет |
| GCSViewer | грани GemCad | фиксированный свет | нет | нет | диагностика граней/ярусов | не про внешний вид |
| Crystal Shader | меш | screen-space | нет | нет | дешёвый стиль | не физика |
| Наш движок | half-space planes | 3 студии + фонарик | до 7 | 3 λ | включения, цветовые зоны, backlight | нет multi-view/диагностики |

## 3. Главные идеи, которые стоит забрать

### 3.1. Два уровня представления камня

1. **Точные плоскости граней** — для физического рейтрейсинга.
2. **Back-face normal/depth buffer** — для дешёвого real-time прохода
   (два прохода: задние нормали, затем передняя поверхность).

Это даёт возможность иметь:
- физический режим;
- быстрый режим для витрины/карточек;
- диагностический режим без преломления.

### 3.2. Считать не «картинку», а путь

- вход через грань;
- Fresnel: отражение + преломление;
- TIR;
- до N внутренних отражений;
- поглощение по длине пути;
- выход через грань;
- окружение/фонарик.

GemRay и Shader diamond показывают, что даже 10–25 отражений дают
убедительную структуру. Наш лимит 7 можно поднять для «красивых» камней
или включать адаптивно.

### 3.3. Дисперсия через длины волн, а не через «радужный фильтр»

- 3 канала (R/G/B) — минимум.
- Лучше — 6–16 длин волн или спектральная выборка.
- IOR можно задавать по Коши: \(n(\lambda)=A+B/\lambda^2\).
- Это даёт «огонь» на гранях и хроматические каустики.

### 3.4. Окружение важнее «лампы»

- GemRay использует случайное небо с пятнами и софитами, а не одну лампу.
- Three.js использует PMREM room environment.
- Нужны:
  - тёмный фон;
  - мягкие окна/софтбоксы;
  - верхний/боковой свет;
  - тень головы наблюдателя (чёрный круг за камерой);
  - фонарик как отдельный источник.

### 3.5. Тень головы

Маленькая, но сильная идея GemRay: за зрителем находится тёмная «голова»,
которая блокирует часть окружения. Из-за этого камень выглядит контрастнее,
а не залитым равномерным светом.

### 3.6. Диагностический режим

GCSViewer делает то, чего не должен делать физический рендер:

- ортогональные виды: сверху, снизу, сбоку, 3/4;
- плоская затенённая отрисовка;
- цвет по ярусам огранки;
- отдельная штриховка frosted-граней.

Это нужно **для огранки**, а не для витрины. Игрок должен видеть, где
грани встретились, где ярус не на месте, где рундист неровный.

### 3.7. Frosted facets

GCSViewer отдельно показывает матовые/«морозные» грани. У нас есть
`kind = frost/girdle`, но в интерфейсе это почти не читается. Стоит:
- отдельная штриховка;
- другой блик;
- явная подпись в плане/осмотре.

### 3.8. Оптимизации

- Симметрия камня (GemRay) — можно считать 1/4 или 1/8 и зеркалить.
- Подсказки последней грани для соседних лучей.
- Таблица затухания.
- Многопоточность CPU.
- Half-res + temporal accumulation + denoise на GPU.
- Back-face normal pass для дешёвого режима.

### 3.9. Что не брать

- **Screen-space GrabPass** как основной рендер: красивый, но не физика.
- **Один вход + один выход** как единственную модель: теряется TIR и
  внутренняя структура.
- **Плоский GCSViewer** как товарный вид: он нужен только для диагностики.

## 4. Что это значит для «Грани»

### 4.1. Три режима рендера

1. **Physical** — текущий path tracer: грани, TIR, включения, цветовые зоны,
   контактный задний фонарик.
2. **Fast** — два прохода: back-face normal buffer + простая рефракция
   по окружению; для карточек, витрины, слабых GPU.
3. **Diagnostic** — плоская затенённая огранка, ортогональные виды,
   tier-цвета, frosted-грани; для станка и разметки.

### 4.2. Ближайшие улучшения физического режима

- Поднять лимит внутренних отражений с 7 до 10–12 для крупных камней.
- Добавить **тень головы** в окружение.
- Сделать **несколько моделей окружения** (студия, тёмный фон, витрина).
- Добавить **спектральную выборку** (хотя бы 6 длин волн).
- Улучшить **каустики** от контактного фонарика.
- Добавить **denoise/temporal accumulation**.

### 4.3. Ближайшие улучшения диагностики

- Ортогональные виды table/pavilion/side/3-4.
- Tier-цвета для граней.
- Отдельная штриховка frost/girdle.
- Показ «встреч» граней и ошибок симметрии.
- Переключатель «физический / диагностический».

### 4.4. Ближайшие улучшения fast-режима

- Back-face normal buffer.
- Один вход + один выход с env map.
- 3 длины волны.
- Fresnel Schlick.
- Ограничение по размеру/качеству.

## 5. Итог

Лучшие идеи из других реализаций:

1. **Точные грани + аналитическое пересечение** — база физики.
2. **Back-face normal pass** — дешёвый real-time режим.
3. **Много внутренних отражений** — структура камня.
4. **3+ длины волны и Коши** — настоящий «огонь».
5. **Богатое окружение + тень головы** — контраст и объём.
6. **Диагностические ортогональные виды + tier-цвета** — работа огранщика.
7. **Frosted facets** — честная передача стадии шлифовки.
8. **Оптимизации**: симметрия, hit hints, LUT, half-res, denoise.

Не стоит тащить screen-space GrabPass как основную физику и плоский
GCSViewer как товарный вид. Это вспомогательные режимы, а не замена
рейтрейсингу.
